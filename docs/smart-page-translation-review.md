### 14.2 需要补齐的设计

- 结构化输出兼容性：自定义 OpenAI 兼容接口与本地模型对结构化输出支持不一，需定义"模型能力不匹配"的判定方式，以及不支持时回退到 JSON 文本解析还是直接使用本地规则。
- 缓存粒度：首版仅会话内缓存，同站点导航在每个页面重复分类，信息流页面会较快耗尽预算。需说明首版不做站点级缓存（host 加结构指纹）的理由，并列为后续项。
- 预算模型：仅按标签页限流时，多标签页调用量线性增长，需增加全局或按 Provider 的上限。分类与翻译共享 Provider 限流，分类排在翻译队列后容易超过 2 秒等待上限，需明确分类请求的优先级或独立通道。
- 等待态流转：补充疑似区域进入视口后的状态流转，说明分类返回或超时后由谁重新触发翻译，以及如何与视口驱动的翻译机制衔接。
- DOM 监听范围：全页启用文本变化监听在计时器、行情、实时计数类页面开销较大，建议限定为已分类区域。
- 页面级覆盖的生命周期：Popup 的"当前页全部内容"为会话覆盖，而路由切换会重建会话，需明确 SPA 内跳转后覆盖是否保留。

### 14.3 验收指标调整

- 跳过率按区域数统计，保留率按字符数统计，单个被误跳过的评论区在字符占比中可能低于 0.5%。增加"阅读区域误跳过数"指标，关键页面要求为 0。
- 为 99.5% 与 90% 两项目标补充标注页面集的规模、标注规则和维护人，保证结果可复现。
- 性能验收增加每页平均分类调用次数与输入 token 数，作为费用基线。

### 14.4 结论

方案可进入细化设计。定稿前需完成 D1 至 D4，14.2 与 14.3 的内容可在细化设计中补入相应章节。

#### 14.6.2 次要问题

- 预算参数重叠：每批 12,000 字符乘以 Provider 6 批为 72,000，超过 60,000 字符上限；全局 12 批为 144,000，超过 120,000。批次上限与字符上限有一项实际不会触发。首版可只保留标签页与全局两层预算。
- 额度组归组依据：9.1 节使用凭证本地摘要归组并持久化到会话存储。使用 `providerId` 与规范化 Base URL 即可归组；若保留凭证摘要，需写明使用带密钥的哈希。
- 7.6 节规则冲突："完成入队后取消该单元观察"与"就绪单元再次进入预加载范围后提交"表述冲突，需写明后者只适用于就绪但尚未入队的单元。
- 12.4 节三次重复运行未说明汇总方式，需明确是三次均达标，还是取均值或最差值。
- 6.4 节提到"用户主动重试时清除能力记录"，第 10 节没有对应的用户入口。
- 第 11 节仍写"预计涉及十余个文件"。加上第 0 阶段、共享准入与评估设施，实际规模明显更大，建议更新估算以便排期。

#### 14.6.3 结论

第一轮的 D1 至 D4 已落实，方案可作为第 0、1 阶段的实施依据。R3 与 R5 需要在第 0、1 阶段开工前确定；R1、R2、R4 需要在第 2 阶段定稿前解决；R6 需要在启用新安装默认值前补齐。14.6.2 的内容可在细化设计中修订。

#### 14.8.2 次要问题

- 端点级空闲无法精确判定：现有网页与字幕队列按功能全局创建（`src/entrypoints/background/translation-queues.ts:162`），不区分端点。9.2 节"无法归属端点时按整体繁忙回退"在首版中会成为常态，建议直接写为"相关翻译队列整体空闲"，避免实现时追求无法获得的端点级判断。
- 首屏批次与正文翻译共享端点限流：首屏分类与正文翻译同时请求同一 Provider，可能使翻译收到 429 并触发重试。每个文档最多 1 批，风险有限；建议写明为已接受风险，并在费用报告中统计首屏分类后翻译侧 429 的比例。
- 评估耗时未估算：100 个布局用例乘 2 种模式乘 3 次重复，加上每次 60 秒回放与额度恢复等待，单轮评估约十余小时并产生 AI 费用。排期需包含这部分，或将 AI 组的三次重复限定在验收集。
- 评审记录篇幅：第 14 节已约 100 行，且 14.7 节声明覆盖 14.5 节的部分处理，读者需要来回对照。定稿时建议将第 14 节移至单独的评审记录文件，正文只保留现行设计。

#### 14.8.3 结论

第 2、3 阶段可按当前正文细化实现。T1、T2 决定第 0 阶段是否仍作为前置条件，需要在开工前确定；T3 关系到 AI 跳过的安全性，需要在第 2 阶段前补齐；T4、T5 影响默认启用的验收，需要在建立页面集前修订。14.8.2 的内容可在细化设计中修订。

### 14.12 第五轮评审结论：评审结束

本轮原则：不过度设计与测试，保持最短实现路径。第 14.11 节的回复已落实到正文，S1 至 S8 全部收敛；第 14.10.2 节要求保留的范围分离、AI 默认关闭及费用说明、P1 至 P6 与结构条件、存疑放行与迟到失效均在正文中保留。现行设计没有阻断实施的问题，评审到此结束。

实施中顺带处理以下两点，不需要再修订设计：

- 第 7.3 节的包含检查以现有外层父节点为界。段落直接位于 `body` 或大型布局容器下且与侧栏、导航为兄弟节点时，整单元会回退双语。第 12.3 节的本地评估顺带记录各样本的双语回退单元占比，占比偏高时再考虑在节点引擎方案中细化拆分。
- 第 6.4 节的 Provider 停用状态不面向用户展示。若实现时 AI 开关旁已有状态位置，可显示"本次已回退本地规则"；没有则不新增入口。

后续意见以实现 PR 评审为准，不再追加设计评审轮次。
